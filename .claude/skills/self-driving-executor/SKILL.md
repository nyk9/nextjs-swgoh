# Self-Driving Executor

このスキルは、1つの大きな依頼を `Planner -> Subplanner -> Worker` に分解して、停止せずに完了まで進めるための実行ルール。

## 適用条件

次のいずれかに該当したら適用する。

- タスクが大きく、1回で完了条件を満たしにくい
- 複数機能にまたがる修正（例: API + UI + データ層）
- 並列で進めたほうが早い
- 要件が曖昧で、先に調査・分解が必要

## 役割

### Planner

- ユーザー要求から「完了条件」を先に固定する
- 依存関係つきで 3-10 個の実行タスクに分解する
- 各タスクに責務・対象ファイル・検証方法を明記する
- 進行中に新情報が出たら、計画を更新する

### Subplanner

- Planner から受けた範囲だけをさらに分解する
- 競合しにくい単位で Worker タスクを切る
- Worker の結果を評価し、次の具体タスクを再配布する

### Worker

- 与えられたスコープのみを実装・検証する
- 不要な横展開や大規模リファクタをしない
- 完了時に「変更点・検証結果・懸念点」を1つの引き継ぎとして返す

## タスクチケット形式

全タスクを以下の形式で定義する。

```md
## Task: <短いタイトル>

Owner: Planner | Subplanner | Worker
Scope: <対象範囲>
Out of scope: <やらないこと>
Files: <主な対象パス>
Done when:

- [ ] 条件1
- [ ] 条件2
      Validation:
- <実行コマンド1>
- <実行コマンド2>
```

## 実行ループ

1. Planner が完了条件と初期タスクを作る
2. Worker が実装し、ローカル検証まで実施する
3. 結果を引き継ぎ形式で返す
4. Planner が差分を再評価し、次タスクを更新する
5. 完了条件を満たすまで繰り返す

## 引き継ぎ形式（Worker -> Planner）

```md
### Handoff

- 変更概要: <何を変えたか>
- 変更ファイル: <path一覧>
- 検証: <実行したコマンドと結果>
- 未解決: <残課題 or なし>
- 次の推奨タスク: <1-3件>
```

## このリポジトリ向け制約

- パッケージマネージャーは `bun` を使う
- 主要検証コマンド:
  - `bun run test`
  - `bun run build`
  - 必要時 `bun run generate`
- Prisma を使うページでは dynamic 設定を壊さない
- `react` と `react-dom` のバージョン整合を維持する
- 既存の未関連変更は巻き戻さない
- 指示がない限り commit / push はしない

## 失敗しやすいパターン

- 完了条件より先に実装を始める
- タスク境界が曖昧で同じファイルを競合編集する
- 「あとで対応」を残して終了する
- 検証コマンド未実行のまま完了宣言する

## 品質ゲート

完了前に必ず確認する。

- [ ] ユーザー要求の完了条件を満たした
- [ ] 影響範囲の主要コマンドが成功した
- [ ] 変更理由を説明できる
- [ ] 未解決項目がある場合は明示した
